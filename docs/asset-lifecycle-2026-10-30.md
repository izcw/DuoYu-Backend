# 用户图片生命周期与清理（2026-10-30）

## 已处理的问题

1. 网址图标切回自动/文字模式仍保留上传图片，造成不可见引用。新保存值不再保留闲置图片；历史配置按真实启用模式计算引用。模板快照也排除闲置图片。
2. 同步准备会处理变更前的数据，旧图片可能因此重复上传。现在历史base只转成哈希用于三方比较，不上传；新值的显式上传会续期，即使同一图片曾被删除也能重新上传。
3. 离线超过上传缓冲时间的待发送操作，会在重放前续传实际修改字段中的图片。历史base不续传，避免无效旧文件反复回到云端。
4. 远端删除壁纸后，本机投影曾只新增、不删除旧缓存。现在删除对应本地壁纸记录并退回每日壁纸，清除旧启动预览。
5. 管理端文件列表现在显示真实引用数量并提供删除。未引用图片确认后删除；引用中的图片必须再次明确确认移除使用位置，生成一个正常同步修订，用户设备联网后同步更新。管理员强删不修改发布模板的独立资源副本。

## 清理规则

| 情况 | 处理 |
| --- | --- |
| 被图标、壁纸、其他收藏数据继续使用 | 保留；同一账号共享图片只在最后引用消失后释放 |
| 被未解决的同步冲突引用 | 保留，等待用户处理；管理员明确强删可覆盖此保护 |
| 曾被引用、后来删除或替换 | 同步提交时释放；刚上传不足10分钟时暂缓，保护文件上传和数据提交之间的窗口 |
| 上传后一直未提交引用 | 24小时后回收 |
| 磁盘上有文件但数据库无记录，或残留上传临时文件 | 满24小时后回收；只处理合法用户目录和受控文件名，跳过目录/符号链接 |
| 本机图片缓存 | 无待同步操作和未解决冲突时，删除超过24小时且无云端有效引用的缓存 |
| 已发布模板/官方资源及备份中的副本 | 独立保留，避免删除其他用户正在使用的共享内容；备份沿用14天保留策略 |

后台约每分钟检查一次。正常图片失去引用后，管理端记录与配额会释放；磁盘删除由持久化队列完成，重启继续。删除/替换必须先成功同步，离线设备尚未上传的本地操作不会瞬间影响云端。

## 一致性和安全

- 上传、同步提交、引用核对及清理使用同一账号行锁，避免跨设备竞争。
- 数据库先删除记录并写入清理队列，磁盘清理可重试。清理前再核对数据库，旧清理请求不会误删同哈希重新上传的文件。
- 管理员删除保留Cookie、Origin、CSRF和审计；普通账号无法调用管理删除接口；拒绝未经确认删除正在使用的图片。
- 不保留所有历史修订里的图片引用来阻止清理，否则僵尸文件永远不能释放。当前实体和未解决冲突受保护，旧历史/备份遵循各自保留策略。
- 备份和物理清理共享PostgreSQL会话锁。备份同时保护数据库快照和图片归档，避免文件被删在两者之间。关闭备份子进程的输入管道会释放锁，进程异常不会留下永久锁。
- 本机缓存收集在IndexedDB事务中核对待发送、冲突和影子数据，避免与其他标签页写入竞争。

## 测试与发布

后端Go 10项集成测试通过，涵盖管理员强删共享引用、壁纸回退、同步修订、CSRF、普通用户隔离、10分钟/24小时保护、冲突保护、磁盘孤儿、旧删除任务与重新上传竞争、备份锁。

同步引擎17项测试通过，新增引用释放、持久化队列、上传缓冲和历史删除不依赖已删除图片。扩展资产单测覆盖base不上传、显式重新上传、隐藏图片排除、本地缓存保护；实际扩展浏览器测试覆盖壁纸上传和删除。管理端浏览器测试验证文件预览及删除后列表刷新。跨浏览器同步、离线重连、冲突处理、JSON导入和PostgreSQL持久化回归通过。Go vet、前后端构建和类型检查通过。

后端和管理端已部署到宝塔Go项目duoyu_backend，发布前完成加密备份。线上两种数据库运行角色的清理权限核对通过；新备份任务成功，恢复dry-run校验通过，未执行生产恢复或代替管理员点击强删真实用户图片。服务器核查时物理删除队列为空。

扩展生成于DuoYu-Extensions/.output/chrome-mv3，需在浏览器扩展管理页重新加载以启用新增按钮及客户端修复。本轮未提交/推送Git。

## 后续建议

数据规模扩大后，建议将图片迁至支持生命周期规则的对象存储，并在管理端增加清理次数、释放空间、失败队列和文件最后使用时间的统计。当前单机方案已经实现引用保护与可重试清理；未来多实例部署应沿用数据库协调和共享对象存储，不能各节点各自删除本地副本。
