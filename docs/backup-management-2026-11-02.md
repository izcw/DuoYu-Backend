# 用户与系统备份

## 用户备份

- `sync_changes` 成功插入时，在同一 PostgreSQL 事务中保存 `sync_user_backups` 完整快照，包括数据集 epoch、云端版本、实体和引用资源。事务失败不留记录，幂等重试不重复备份。
- 按账号锁串行捕获与轮换，每个账号保留最近 5 份，超过后移除最旧快照。已有账号部署时初始化一份当前数据，不伪造历史记录。
- 管理端“备份管理 → 用户数据备份”按用户显示头像、昵称、份数和最后备份时间，详情可下载 ZIP。ZIP 包含 `snapshot.json` 和 `assets/<SHA256>`，不包含登录凭证。此包是服务端快照格式，不是扩展导入 JSON 格式。
- 当前使用和最近 5 份快照引用的上传文件都受到物理清理保护。用户删除/替换图片后，历史备份仍可恢复图片；快照轮换后，无引用文件由定期清理回收。历史图片不计入用户当前 100MB 上传配额，需另行监控服务器备份空间。
- 同步运行账号仅有本账号 RLS 权限；管理员下载接口需要超级管理员会话。下载和文件清理共享协调锁，避免下载期间图片被删除。

## 系统全量与增量备份

- systemd `duoyu-sync-backup.timer` 每天 **Asia/Shanghai 00:00** 执行，Persistent=true；首次或距上次全量已满 7 天做全量，其余做增量。可在管理端手动创建两种备份。
- 全量捕获 PostgreSQL 自定义格式转储和用户/官方上传图片。它是业务数据备份，不包含部署程序、环境变量和加密密钥。
- 每次全量创建独立命名空间；增量按 4MB 文件块去重，只新增变化的块。数据库转储本身仍完整生成，因此数据库变动较大时增量新增量可能接近完整转储大小。不是 WAL 连续归档或任意时间点恢复。
- 每条记录含完整重建清单，块使用 AES-256-GCM 加密并校验 SHA-256。临时写入、fsync、原子发布后才清理旧记录；失败不会替换有效恢复点。
- 最多保留 7 条记录。删除旧清单后，只清理全部保留清单均不再引用的块。因此最早全量记录被轮换后，其余增量仍可独立重建，不依赖已删除的链头。
- 旧版数据库/图片加密文件按同一恢复点成对轮换，迁移期与新记录合计最多 7 份。新管理页显示新格式的全量/增量记录。
- 管理端下载将清单和全部所需加密块打包 ZIP；增量下载也是完整可恢复包，下载大小可能大于“本次新增存储”。加密密钥始终不经 API 下载。
- 存储：`/www/backup/duoyu-sync/<UUID>.record.json`、`objects/<namespace>/<SHA256>.enc`；密钥：`/www/server/duoyu-sync-backup.key`。
- 文件清理、备份、下载通过 PostgreSQL advisory lock 52615262 协调；后台备份任务使用独立系统单元，最大执行 40 分钟。Go 手动任务限时 45 分钟。

## 恢复与验证

在原服务器可先执行无破坏性校验：

```sh
node /www/wwwroot/duoyu-sync/src/restore-system.mjs --id <备份UUID> --dry-run
```

下载 ZIP 恢复前，需将清单和 objects 目录放回受控备份目录，并单独准备原加密密钥。实际恢复要求 root 和显式确认：

```sh
node /www/wwwroot/duoyu-sync/src/restore-system.mjs --id <备份UUID> --confirm duoyu_extensions
```

恢复会先校验 GCM、块哈希、完整文件哈希及 pg_restore 目录，再使用现有维护模式工具停服、恢复数据库与图片、轮换数据集 epoch，避免离线旧版本直接覆盖恢复后的数据。应先在隔离环境演练；本次未覆盖线上数据库。

## 验证记录

- Go 测试与 vet：用户 5 份轮换、事务回滚、图片保留及到期清理、下载 ZIP、普通用户禁止访问、系统包下载和缺块拒绝。
- Node 18 项测试：同步回归、重复请求不增加用户备份、超过 7 份仍可恢复、全量头轮换后的增量恢复、损坏拒绝、路径验证。
- 管理 UI：用户份数和详情下载、系统类型切换、壁纸等原有流程；扩展 PostgreSQL 云同步集成测试通过。
- 线上实际运行账号（清空 supplementary groups）成功创建全量和增量备份，并确认可读清单和所有加密块。
- 新增量备份完整恢复 dry-run 通过，无线上数据库/服务数据覆盖；定时器下次为 2026-11-03 00:00:00 CST。

备份仍保存在同一服务器，不能抵御整盘损坏或服务器丢失。应将完整下载包和加密密钥分开保管，并配置异地备份目的地后再接入自动异地复制。
